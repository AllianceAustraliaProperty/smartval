SmartVal database and PDF performance deployment

Backend and pdf-worker share the backend build image. Build the backend before
starting either service. The renderer has one Gunicorn process, six HTTP threads,
one render thread and a queue limited to two waiting jobs. Do not scale its
Gunicorn process count: each process would create another queue and renderer.
The worker has its own network shared only with the backend, no public ports,
no application env_file or uploads mount, a read-only root, and 2 CPU / 2 GiB limits.

Typical production deployment (from repository root):
  /usr/local/bin/docker-compose build backend
  /usr/local/bin/docker-compose run --rm --no-deps backend python ensure_performance_indexes.py
  /usr/local/bin/docker-compose up -d --no-build pdf-worker backend

The index step is idempotent and never changes report data. The dashboard's
paginated listing now returns page and exact count in one aggregate. Unbounded
callers retain a normal cursor. Ordering uses updatedAt then _id for stable ties.

Images, HTML and PDFs are cached for five minutes, capped at 96/64/96 MiB in the
backend's /tmp tmpfs. Files are private and disappear when the container restarts.
Every HTML request still reads the current report from MongoDB. Its full content,
template/asset metadata, rendering configuration and current date form the key.
Report field changes therefore invalidate HTML immediately even if updatedAt was
not updated; PDFs are keyed by complete HTML. Replacing remote image content at
the same URL can take up to the image and HTML cache lifetimes to propagate.
Cache writes are atomic; cross-process locks collapse duplicate generation.

PDF overload/unavailability returns 503 and Retry-After: 5 through existing PDF
routes. No asynchronous frontend protocol change is required. New browser
contexts isolate reports; Chromium is reused and recycled every 50 renders.
Image sizing and PDF compression settings are unchanged.

Verification:
  python -m unittest tests.test_performance -v (inside backend environment)
  backend /health and worker /health must return 200.
  Confirm report_listing_updated_at appears in MongoDB explain without SORT.
  Public protected APIs should continue requiring authentication.

2026-10-13 server-side benchmark, one existing 14-page report:
  Listing: 0.51 s -> 0.255 s (403 active reports; exact count preserved).
  First HTML + PDF: 36.22 s -> 5.90 s.
  Repeated HTML + PDF: 0.27 s.
  Existing residential, commercial (12 pages), and invoice (1 page) rendered.
  Identical HTML retained all page text ignoring extraction whitespace; font
  names and page count matched. Visual layout checked. Existing set-based room
  descriptions can order labels differently between separate HTML renders.
  Five concurrent uncached jobs: three rendered, two returned 503; backend
  health responded 200 in 4 ms during rendering.

Rollback image: smartval-backend:before-performance-20261013. Original Compose
and changed source files are saved in the private performance backup directory
on the server before deployment. Restore those files and recreate backend using
the rollback image; the extra Mongo index is harmless and can remain.
